# P1 使用場景

下列是 P1 正式資料的驗收情境。0.1.2 可透過 MCP 呼叫四組 samples，也可在安裝經審核的 Release snapshot 後使用 `official_snapshot`。Sample 與正式資料都不能直接作為醫療、採檢、申報或採購決策。

## CDC：檢體怎麼採、怎麼送

**使用者：** 接到送驗需求的醫檢師。

**提問：** 「請查麻疹的 CDC 採檢送驗要求，依官方原欄列出採檢項目、目的、時間、採檢量及規定、送驗方式、應保存種類（應保存時間）與注意事項，附手冊版本及頁碼。」

**完成條件：** 回傳內容按官方原始列分開，保留複合欄、條件和例外，不自行拆出容器或送驗前保存指示；每個實際值能回到官方文件。資訊不足時，明確說明缺哪個欄位；樣本模式顯示不可供採檢作業使用。

## NHI：代碼與支付點數

**使用者：** 需要查詢檢驗支付項目的醫檢師或管理者。

**提問：** 「請查 HbA1c 相關健保碼，列出名稱、支付點數、生效期間與備註，附資料來源與更新時間。」

**完成條件：** 保留全部符合的相關項目及生效期間，點數單位清楚，規範無法確認時提供原文入口。搜尋無結果不推論未納入給付；不以點數估算實際申報金額或保證個案可申報。

## TFDA：IVD 許可證

**使用者：** 查核公開產品資料的醫檢師、採購或 IVD 從業人員。

**提問：** 「請找 HPV DNA 相關 IVD 許可證，分列品名、效能、申請商、製造商、有效日期與註銷資訊，附官方來源。」

**完成條件：** 說明搜尋與 IVD 篩選範圍，保留完整許可證識別與廠商角色。資料不足時不宣稱許可證仍有效；效能欄位不可擴寫成產品原文未宣稱的能力。

## Workshop 驗收

先展示樣本模式與來源警示，再在已完成正式資料驗證的版本展示真實查詢。參與者需能自行核對一筆官方資料，並理解資料版本與不確定處。

邀請參與者自願回報：是否完成原本的查詢、哪些步驟省下時間、哪些地方仍需回到官方網站。教學回饋與醫院合作詢問透過公開 Issue 的非機密內容開始，不收集病人資料。
